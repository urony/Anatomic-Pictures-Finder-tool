# בונה מבחני אנטומיה

כלי חינמי למורים למדעי הבריאות: מוצאים תמונות אנטומיות ממאגרים פתוחים, מסמנים עליהן מספרים וחצים, מסדרים אותן בעמוד עם טבלת תשובות ריקה, ומורידים **PDF** להדפסה או **Word** לעריכה.

* אתר סטטי בלבד — בלי שרת, בלי הרשמה, בלי מפתחות API ובלי עלות. כל העיבוד קורה בדפדפן של המורה.
* התמונות אינן נשמרות במאגר הקוד; הן נשלפות בזמן אמת מהמאגרים.
* עברית מלאה, RTL.

## זרימת העבודה למורה

1. **חיפוש ובחירה** — מקלידים איבר/מערכת בעברית (למשל "כליה", "בלוטת התריס"). הכלי מתרגם דרך מילון מקומי ומחפש ב-Wikimedia Commons וב-Wellcome Collection. אפשר להגדיל כל תמונה ולראות מקור, יוצר ורישיון לפני הבחירה. אפשר גם להעלות תמונה מהמחשב.
2. **סימון** — לחיצה על המבנה מניחה מספר; "מספר עם חץ" — גוררים מחוץ למבנה אל המבנה. אפשר להזיז, לשנות מספר, למחוק ולבטל (Ctrl+Z).
3. **עימוד** — טבלת תשובות בסגנון בחינות הבגרות (מספר, שם בעברית, שם באנגלית, תפקיד; כל עמודה אופציונלית, חוץ ממספר ושם בעברית), בשני מצבים: שורה לכל מספר שסומן, או שורות ריקות שבהן התלמיד בוחר מספרים. הנחיה עריכה מעל הטבלה. הטבלה תופסת בדרך כלל כרבע עמוד.
   עוד: תבנית "מבחן עם טבלה" / "תמונות בלבד" / "פריסה מותאמת", 1–6 תמונות בעמוד, שינוי סדר בגרירה, יחס טבלה/תמונות, A4/Letter, לאורך/לרוחב.
4. **הורדה** — PDF, Word, או PNG/JPEG של עמוד או של תמונה בודדת. אפשר גם להדפיס ישירות. אפשר לשמור את הפרויקט לקובץ ולפתוח אותו שוב.

## פיתוח מקומי

דרישות: Node.js 20 ומעלה.

```bash
npm install
npm run dev        # שרת פיתוח ב-http://localhost:5173
npm test           # בדיקות יחידה (עימוד, רישוי, מילון, קובץ פרויקט)
npm run build      # בדיקת טיפוסים ובנייה לתיקיית dist
```

## מאגר המורים (תמונות משלנו)

תמונות שמעלים לתיקייה `public/library/` מופיעות בחיפוש כמקור ראשון, "מאגר המורים", בלי שום קוד נוסף.

* **שם הקובץ הוא מילות החיפוש** באנגלית: `kidney_nephron.png`, `heart_valves.jpg`. אפשר גם תיקיות משנה (`heart/valves.png`) — שם התיקייה נחשב גם הוא.
* **קרדיט (אופציונלי)**: שורה בקובץ `public/library/credits.csv` (`file,author,license,source`). אם יש רישיון — הקרדיט מודפס אוטומטית במבחן. בלי שורה, התמונה נכנסת עם הסימון "הועלתה על ידי צוות הכלי".
* **תמונות כבדות לא מאטות את האתר:** בכל בנייה נוצרות אוטומטית (בעזרת `sharp`) גרסת אתר WebP עד 2000px לשימוש במבחן וממוזערת 480px לתצוגת החיפוש (`public/library/_web`, `_thumbs`; לא נשמרות ב-git). קובצי המקור נשארים ב-GitHub אך אינם נכנסים לאתר המפורסם (`scripts/prune-dist-library.mjs`).
* **נושאים:** תמונה נכנסת לנושא לפי מילות המפתח שבשם הקובץ/התיקייה, מתוך רשימה מכוונת לכל נושא ב-`src/lib/topics.ts` (`libraryKeywords`). תיקיות ושמות כמו `heart/heart_03.png`, `female_reproductive_system/ovary_01.jpg`, `pituitary_gland/...` עובדים מיידית. כדי שנושא חדש יכלול תמונות, מוסיפים לו מילים ברשימה.
* האינדקס `index.json` נבנה אוטומטית בכל `npm run build` / `npm run dev` (וגם בפרסום ב-GitHub Actions); אין לערוך אותו ידנית.
* **העלאה**: בדף המאגר ב-GitHub נכנסים לתיקייה `public/library` → Add file → Upload files, גוררים את התמונות ולוחצים Commit. הפרסום מתעדכן אוטומטית תוך כדקה. מהמחשב: מעתיקים את הקבצים לתיקייה ואז `git add . && git commit -m "add images" && git push`.

## הדפסה בשחור-לבן

בשלב העימוד, "צבע התמונות (להדפסה)": צבעוני / גווני אפור / שחור-לבן בניגודיות מוגברת (עם מחוון עוצמה). ההמרה מתבצעת על התמונות בלבד (מתיחת טווח ואז הגברת ניגודיות), לפני הוספת המספרים, ונכללת בתצוגה, ב-PDF, ב-Word, בתמונה המיוצאת ובהדפסה. הכיסויים שהוספתם (הסתרת טקסט) עוברים את אותה המרה.

## הסתרת טקסט שמודפס בתוך תמונה

בשלב הסימון, הכלי "▭ הסתר טקסט": גוררים מלבן על כיתוב שמודפס בתוך התמונה (למשל שמות המבנים באיור). המלבן מתמלא אוטומטית בצבע הרקע שסביבו (דגימת חציון מטבעת סביב המלבן), ואפשר להחליף ללבן/שחור, להזיז, לשנות גודל ולמחוק. ההסתרה נשמרת בפרויקט, נכללת בתצוגה, ב-PDF, ב-Word ובתמונה המיוצאת, ונתמכת בביטול/שחזור. אין בזה AI: זו כיסוי ידני. ברקע מורכב (צבעוני או מעבר צבעים) ייתכן שהכיסוי יראה, ואז כדאי לבחור לבן/שחור או לחתוך את התמונה לפני השימוש. רישיון ND (ללא נגזרות) אינו מתיר עריכה.

## חיפוש לפי נושא

הכפתורים המהירים (לב, כליה, כלי דם, תאי דם, רבייה זכרית/נקבית, אנדוקרינולוגיה ובלוטותיה) מחפשים את **כל מונחי הנושא** מתוך מסמך המונחים — למשל "מערכת הרבייה הנקבית" מחפש נרתיק, רחם, חצוצרות, שחלות ועוד — ומציגים את התוצאות בקבוצות לפי מונח, 6 מונחים בכל פעם ("עוד מונחים מהנושא"). הגדרת הנושאים ב-`src/lib/topics.ts`.

## פרסום ב-GitHub Pages

1. מעלים את התיקייה למאגר ב-GitHub (ענף `main`).
2. ב-GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. כל push ל-`main` מריץ את `.github/workflows/deploy.yml` (בדיקות, בנייה, פרסום).
4. הכתובת תהיה `https://<משתמש>.github.io/<שם-המאגר>/`.

האתר בנוי עם נתיבים יחסיים (`base: './'`), ולכן עובד גם בתת-נתיב וגם בדומיין מותאם, בלי הגדרה נוספת.

### רישוי וקרדיט

* הרישיון נקרא מנתוני המקור ולא מנוחש. ברירת המחדל מציגה רק תמונות עם רישיון ברור (CC0, נחלת הכלל, CC BY, CC BY-SA). תמונות NC / ND / לא ברור מוסתרות עד שמסמנים "הצג גם תמונות עם רישיון לא ברור או מוגבל".
* בכל מסמך נוצר קרדיט אוטומטי בתחתית העמוד (כותרת, יוצר, מקור, רישיון עם קישור, כתובת המקור, "נוספו סימונים"). אפשר לכבות אותו בשלב העימוד, אך רישיונות רבים מחייבים קרדיט.
* מנגנון הרישוי הוא מידע עזר ולא חוות דעת משפטית. הכלי אינו מאמת את הדיוק האנטומי של תמונה — ההחלטה בידי המורה.

## עדכון מילון המונחים

המילון נבנה מהמסמך **`מילון מונחים.docx`** (טבלאות: עברית | אנגלית, תחת כותרות של תחומים) בתוספת מונחי בסיס (`scripts/base-terms.json`: ריאות, מוח, שלד, שרירים ועוד).

לעדכון: עורכים את המסמך ומריצים

```bash
npm run build:terms
```

הפקודה יוצרת מחדש את `public/data/anatomy-terms.json` (נטען בזמן ריצה). בכל פריט: `he` — שמות בעברית (מפוצלים לפי " / "; יש גם תיקוני כתיב נפוצים בסקריפט), `en` — מונחי חיפוש באנגלית (הראשון משמש לחיפוש, האחרים מוצעים כ"נסו גם"). מונחים אנגליים קצרים ורב-משמעיים (Ventricle, Fundus…) מקבלים הקשר אוטומטי לחיפוש (`EN_CONTEXT` בסקריפט). שורה בלי אנגלית (כמו "אלקטרופיזיולוגיה של הלב") מדולגת.

## מגבלות ידועות

* **ה-PDF מכיל כל עמוד כתמונה חדה (~216 dpi)** — כך העברית והמספרים נראים זהים בכל מחשב, אך הטקסט ב-PDF אינו ניתן לסימון/חיפוש. ב-Word הטקסט והטבלה עריכים.
* ב-Word כל תמונה מגיעה עם הסימונים כחלק ממנה (אין עריכה נפרדת של סימון בתוך Word).
* סינון "צבעוני / שחור-לבן" מחושב בדפדפן לפי התצוגה המקדימה — הערכה, לא הבטחה. סינון סוג התמונה (איור/צילום/הדמיה/היסטולוגיה) מבוסס מילות חיפוש ב-Commons ולכן משוער.
* חיפוש ב-Wellcome מוגבל לאנגלית ולרוב מחזיר איורים היסטוריים.
* רשת בית ספר שחוסמת את wikimedia.org או wellcomecollection.org תמנע חיפוש ושליפת תמונות; הכלי מציג הודעה ואינו עוקף חסימות.
* הכלי מיועד למחשב; במסך קטן מוצגת הודעה.
* נבדק ב-Chromium (Chrome/Edge). Firefox, Safari ופתיחת ה-DOCX ב-Word/Google Docs לא נבדקו בפועל בסביבת הפיתוח.
